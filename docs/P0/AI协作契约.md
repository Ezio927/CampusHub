# AI协作契约

**团队名称：** 不是bug 是特性  
**签署日期：** 2026年4月8日  

---

### 第一条：AI使用原则

1.  **工程师主体责任：** AI仅作为辅助工具，团队成员是代码和文档的最终责任主体。  
2.  **人工审查必经：** 所有由AI生成的内容（包括代码、文档、设计图等）在合入项目仓库或正式文档前，必须经过人工审查与验证。  

### 第二条：AI使用范围

1.  **允许使用的场景：** 
    * a. 需求文档初稿起草、用户故事润色。  
    * b. 通用 CRUD 代码模板生成、单元测试用例自动生成。  
    * c. 复杂算法逻辑的思路咨询、已有代码的重构建议。  
2.  **禁止直接使用（需额外审查）的场景：** 
    * a. 涉及系统核心安全逻辑（如加密、权限校验）的代码。  
    * b. 数据库 Schema 设计及核心架构决策。  
3.  **完全禁止使用的场景：**  严禁在不理解代码逻辑的情况下直接粘贴 AI 生成的复杂函数。  

### 第三条：过程记录要求

1.  **Prompt 日志保留：** 所有与 AI 的关键交互 Prompt 必须完整记录并留存，作为各阶段交付物的一部分。  
2.  **提交记录标注：** Git commit message 必须严格标注标签。AI辅助的代码使用 `[AI-assisted]`，完全手写的代码使用 `[Human-written]`。  
3.  **阶段性反思：** 在每个阶段结束时，必须按要求填写《AI协作反思日志》。  

### 第四条：代码合入规则

1.  **Code Review 机制：** AI生成的代码在合入主分支前，必须通过至少一名团队成员的人工 Code Review。  
2.  **核心代码保底：** 为确保专业能力成长，每位成员在每个编码阶段（Sprint 1 & 2）必须至少包含 2 个完全手写的核心逻辑函数。  

### 第五条：违约处理

* **违约定义：** 包括但不限于伪造 Prompt 日志、提交不带标注的 AI 代码、未履行 Code Review 职责等。  
* **处理方式：** 
    * **第一次发现：** 团队内部通报批评，并由该成员重新完成该任务。  
    * **严重或重复违约：** 记录在《反思日志》中，可能影响该成员在“工程判断力”维度的个人得分。
